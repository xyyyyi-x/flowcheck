# Claude Code 开工与续接提示词

适用：用户用Claude Code接DeepSeek实施本项目。此文档不包含模型供应商密钥或接入设置。
选择模型与接入由用户自行配置；开发计划不依赖付费AI API，也不要求产品包含LLM。

## 1. 首次开工（复制下面整段）

~~~text
请在当前仓库实现“接口回归测试平台”。用户已确认Python/FastAPI后端+简单Vue前端，
目标是Python后端实习项目。你是实现者，必须依据仓库文档工作，不要重新选题。

先依次读取：
1. CLAUDE.md
2. docs/superpowers/specs/2026-11-05-api-regression-platform-design.md
3. docs/contracts/api-v1.md
4. docs/superpowers/plans/2026-11-05-api-regression-platform-plan.md
5. docs/handoff/acceptance.md
6. docs/progress.md

本次只执行T01。先用简短清单说明：
- T01交付物和依赖是否满足；
- 会创建哪些文件；
- 实际验证命令；
- 是否发现文档冲突。
没有真实阻塞就开始，不要只给我另一个计划，也不要一次生成整个项目。

约束：
保持文档规定的技术栈、路由、字段和状态机；不要加入AI聊天、DAG或团队系统。
依据实际版本安装并生成lockfile，不伪造依赖版本。
只在当前项目目录工作；不改全局Git身份，不覆盖用户文件。
不输出.env、密码和Token。不要联网部署或push。
纯函数先失败测试再实现，脚手架用启动/构建验证。
完成后给实际命令结果，更新docs/progress.md，按规则提交本任务，停止等待检查。
如果依赖下载或权限阻塞，说明具体命令与原因，不能把未执行检查写成通过。
~~~

## 2. 完成一项后的续接

~~~text
读取CLAUDE.md、设计规格、API契约、实施计划和docs/progress.md。
先检查git status和当前实现是否与进度记录一致。
执行下一个尚未完成且依赖已满足的任务，只做这一项。
复用已有模块，不重新生成整个工程，不更换框架，不绕过失败测试。
若上一项有未解决失败，先修复并核实，再决定是否能推进。
完成后列出修改、实际测试结果、遗留问题，更新进度并提交。
~~~

## 3. 用户希望一次执行一个里程碑时

~~~text
我授权你连续执行当前里程碑中依赖已满足的任务，仍须逐任务验证与记录，
不得跳过失败项或把多个尚未验证任务一次堆积提交。
遇到会改变API契约/状态机/主要技术栈的选择时，先说明具体冲突和建议；
常规实现细节自行处理。
只完成当前里程碑，不进入下一里程碑。
结束时提供各任务编号、验证证据、未完成原因，并更新docs/progress.md。
~~~

里程碑：
- M1：T01..T06，能通过真实API配置数据，前端尚未完整。
- M2：T07..T11，后台可执行并返回可靠报告/SSE。
- M3：T12..T14，浏览器完整操作和P0验收。
- M4：T15，统计缓存、性能证据与展示材料。

## 4. 新聊天或上下文不足时

~~~text
请不要依据旧聊天记忆猜项目状态。读取CLAUDE.md、docs/progress.md、
设计/API契约和实施计划；检查git status、最近提交和已有测试。
总结已完成、待完成、当前失败与下一任务，不重做已完成模块。
先运行记录中与当前任务相关的最小验证，确认状态后继续。
~~~

## 5. 阶段评审提示词

~~~text
暂不加功能。审查刚完成里程碑是否符合设计/API契约和对应验收编号。
重点检查owner隔离、secret泄露、真实PG事务、run快照、队列重复、
Worker中断、SSE鉴权和前端字段是否一致。
对每个问题给复现条件、文件位置、影响、修复建议；区分已证实与推测。
运行必要检查，不能只读代码后宣称全部通过。
先修复会阻断下一阶段的问题，再更新docs/progress.md。
~~~

## 6. 完成后要求交付

运行docs/handoff/acceptance.md的检查，生成真实docs/verification.md。
README说明安装、配置、迁移、启动、运行测试、演示故障、停止服务。
演示3段：全通过、断言失败、Worker中断。
保留lockfile和迁移，提供截图与架构说明。
简历只写实际完成与测量结果，禁止把合成数据称为线上用户流量。

## 7. 用户检查时看什么

每阶段无需逐行理解所有代码，先查看：
- 是否出现计划外的新框架/服务；
- 是否有真实测试命令和输出；
- 前后端字段是否按同一契约；
- Worker是否真正执行HTTP；
- 报告是否来自数据库而非前端拼接；
- 故障是否能解释，秘密是否在后端就已遮蔽；
- 进度文档是否如实记录未完成检查。

不要仅回复“继续”让模型无限扩张功能。指定任务/里程碑编号，并要求它对照验收交证据。
